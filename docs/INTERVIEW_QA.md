# 🎤 kfirewall: Technical Interview Q&A (Вопросы и ответы к собеседованию)

Этот документ подготовлен для защиты проекта перед техническими лидами и архитекторами системного ПО и сетевой безопасности.

---

### 1. На каком этапе сетевого стека перехватываются пакеты и почему?
**Ответ:**
Пакеты перехватываются на этапе **`NF_INET_PRE_ROUTING`** (хук Netfilter IPv4).
* **Почему именно здесь:** Это самая ранняя точка в сетевом стеке ядра после того, как сетевой драйвер принял кадр и сформировал `sk_buff`, но **до** принятия решения о маршрутизации (`ip_route_input_noref`).
* **Преимущество:** Если пакет подлежит блокировке (Drop), мы отбрасываем его сразу (`NF_DROP`). Ядру не нужно тратить такты процессора на поиск маршрута, выделение сокетов и прогон через транспортный уровень.

---

### 2. Почему для синхронизации используется `spin_lock_bh`, а не `mutex`?
**Ответ:**
* Код Netfilter-хука выполняется в **контексте программного прерывания (`softirq` / bottom half)**, когда сетевая карта поднимает прерывание и ядро обрабатывает входящие пакеты через NAPI.
* В контексте прерываний **запрещено усыплять поток (sleep/schedule)**! Вызов `mutex_lock()` при конфликте пытается перевести поток в сон, что в прерывании вызовет немедленный Kernel Panic (`BUG: scheduling while atomic`).
* Поэтому используется спинлок. Модификатор `_bh` (`spin_lock_bh`) дополнительно отключает обработку нижних половин прерываний на текущем CPU, предотвращая дедлок (когда прерывание вытесняет само себя на том же процессоре).

### 3. Как устроена работа со `struct sk_buff`?
**Ответ:**
`sk_buff` (socket buffer) — фундаментальная структура сетевого стека Linux.
* Пакет содержит указатели: `head`, `data`, `tail`, `end`.
* Сетевой заголовок извлекается через макрос `ip_hdr(skb)` (или смещение `skb_network_header`).
* Из `struct iphdr` извлекаются `saddr` и `daddr` (в сетевом порядке байт — big endian), а также поле `protocol`.
* Если протокол TCP, транспортный заголовок извлекается через `tcp_hdr(skb)` (`skb_transport_header`). Порты переводятся из network byte order в host byte order макросом `ntohs()`.

### 4. Как реализовано управление из User Space и почему использовался `/proc`?
**Ответ:**
* Реализован виртуальный файл `/proc/kfirewall`.
* В ядре зарегистрированы колбэки чтения и записи. При этом учтена смена API в Linux: начиная с версии **5.6**, ядро перешло с `struct file_operations` на `struct proc_ops` (`.proc_read`, `.proc_write`). Мой код содержит макрос версионности `LINUX_VERSION_CODE >= KERNEL_VERSION(5, 6, 0)` для обратной совместимости.
* Чтение файла форматирует ASCII-отчет со статистикой и списком правил.
* Запись парсит простые текстовые команды (`block_ip`, `block_port`, `clear`) с использованием безопасных функций ядра (`copy_from_user`, `in4_pton`, `kstrtouint`).

### 5. Что такое TCP Anomaly Detection (Xmas, NULL scan)?
**Ответ:**
Сканеры безопасности (например, `nmap`) используют нестандартные комбинации TCP-флагов для скрытого сканирования портов в обход простых пакетных фильтров:
* **NULL scan:** Пакет не содержит ни одного флага (`!syn && !ack && !fin && ...`). По RFC 793, закрытый порт должен ответить RST, а открытый порт проигнорирует пакет.
* **Xmas scan:** Установлены флаги FIN, PSH и URG («горит как рождественская елка»). Легитимный трафик никогда не использует такую комбинацию.
* Модуль анализирует флаги в `struct tcphdr` и моментально дропает пакет с логированием предупреждения в `dmesg`, предотвращая сбор информации злоумышленником.

### 6. Что произойдет при выгрузке модуля (`rmmod`)?
**Ответ:**
В функции `kfirewall_exit()` обязательно вызываются:
1. `nf_unregister_net_hook(&init_net, &nf_ops)` — снятие хука из цепочки Netfilter. Если этого не сделать, следующий сетевой пакет вызовет переход по мертвому адресу памяти (Kernel Panic / Oops).
2. `proc_remove(proc_entry)` — удаление записи в procfs.
Выгрузка модуля происходит абсолютно бесшовно для системы: все правила снимаются, а сетевой трафик возвращается к штатной обработке.
